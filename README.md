# Xympia

Личный десктоп-плеер (Electron + React + TypeScript), объединяющий:

## Установка

### 1. Зависимости Node

```bash
npm install
```

### 2. Зависимости Python-сайдкара

```bash
cd python-sidecar
python3 -m venv .venv
source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -r requirements.txt
cd ..
```

Убедись, что `python3` (или `python` на Windows) доступен в PATH — Electron
сам запускает `python-sidecar/server.py` при старте приложения.

### 3. Запуск в режиме разработки

```bash
npm run dev
```

Поднимутся: Vite dev-server, компиляция Electron-кода в watch-режиме и сам
Electron, который дополнительно запускает Python-сайдкар на `127.0.0.1:8799`.

## Вход в приложение

Xympia открывается экраном входа: при первом запуске ты задаёшь локальный
логин и пароль (хранятся только на этом устройстве — соль + хэш через
`scrypt`, без сети). При каждом следующем запуске приложение просит эти же
логин и пароль, прежде чем показать интерфейс. Это отдельная вещь от
привязки Яндекс Музыки и SoundCloud ниже — она защищает сам доступ к
приложению, а не тянет данные из внешних сервисов.

## Привязка аккаунтов (Яндекс Музыка, SoundCloud)

После входа открой профиль (аватар в шапке) → раздел «Аккаунты». Там можно
подключить и отключить каждый сервис отдельно; статус («Подключено» /
«Не подключено») виден сразу.

### Яндекс Музыка

Библиотека `yandex-music` работает через OAuth-токен личного аккаунта.
Самый простой и документированный способ получить токен для персонального
использования — через официальный OAuth-флоу Яндекса с client_id мобильного
приложения Яндекс Музыки

Коротко:
1. Перейди по ссылке авторизации из FAQ библиотеки, залогинься под своим
   аккаунтом.
2. После редиректа скопируй `access_token` из адресной строки.
3. Вставь его в разделе «Аккаунты» профиля — токен сохранится локально
   (через `electron-store`) и дальше запрашиваться не будет, пока не нажмёшь
   «Отключить».

Токен даёт доступ только твоему собственному приложению к твоему аккаунту —
никуда кроме локального сайдкара он не отправляется.

### SoundCloud

Публичный поиск работает и без привязки аккаунта

## Обновление SoundCloud client_id

Публичный `client_id` в `electron/services/soundcloud.ts` может протухать.
Как обновить — см. комментарий в начале файла.

## Структура проекта

```
electron/            # main-процесс, preload, IPC, сервисы SoundCloud/VK
python-sidecar/       # FastAPI-обёртка над библиотекой yandex-music
src/                  # React-приложение (renderer)
build/                # иконка приложения для установщика (icon.png / icon.ico)
```

## Интерфейс

- **Тёмная/светлая тема** — переключатель в шапке (иконка солнца/луны) или
  в профиле. Сохраняется локально и применяется при следующем запуске.
- **Поиск** — строка в шапке ищет одновременно: по уже загруженным спискам
  (лайкнутые, обе волны), по каталогу Яндекс Музыки (`/search/tracks` в
  python-сайдкаре) и по публичному поиску SoundCloud. Результаты показаны
  секциями, поиск по каталогу и SoundCloud — с debounce 350мс.
- **Профиль** — открывается по клику на аватар в шапке:
  - **Username** — постоянный локальный идентификатор в духе Telegram
    (`@username`, 5–32 символа, латиница/цифры/`_`, начинается с буквы).
    После первого сохранения показывается как зафиксированный; смена
    возможна через «Изменить», но приложение переспрашивает подтверждение,
    подчёркивая, что username задуман постоянным.
  - **Аватарка и баннер** — загружаются через системный диалог выбора
    файла, хранятся локально (как data URL в `electron-store`, лимит 6 МБ
    на файл) и никуда не отправляются.

## Установщик (electron-builder)

В `package.json` добавлена секция `build` для `electron-builder`: Windows
(NSIS, с возможностью выбрать папку установки и ярлыками), macOS (DMG) и
Linux (AppImage). Иконка лежит в `build/icon.png` (и `build/icon.ico` для
Windows)

Собрать установщик (нужна сеть — electron-builder скачивает бинарники
Electron под нужную платформу при первом запуске):

```bash
npm install
npm run build        # соберёт renderer (Vite) и electron-код (tsc)
npm run dist          # соберёт установщик под текущую ОС → папка release/
# или прицельно:
npm run dist:win
npm run dist:mac      # только на macOS — для .icns иконки лучше сгенерировать
                       # её отдельно через iconutil из build/icon.png
npm run dist:linux
```

Готовый установщик появится в `release/` (например,
`release/Xympia Setup 0.1.0.exe` на Windows). Python-сайдкар копируется
в установщик как `extraResources`, но пользователю всё равно нужен
установленный `python3` с зависимостями из `python-sidecar/requirements.txt`
